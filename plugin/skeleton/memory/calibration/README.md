# memory/calibration/ — predictive accuracy scoring

This directory holds **calibration state and reports** for the predictive layer. Calibration is the discipline of measuring how often the agent's predictions match outcomes, per actor and per tier, so that systematic biases surface.

Without calibration, the predictive layer is a hallucination engine. Calibration is the feedback loop that makes shadow hypotheses and `/branch-out` simulations honest.

## actor-scores.yaml — the canonical state

`actor-scores.yaml` is the **single source of truth for per-actor numerical calibration**. The schema is documented in `actor-scores.template.yaml`. The structure is:

```yaml
version: 1.0
last_updated: <YYYY-MM-DD>

actors:
  <stakeholder-slug>:
    total_hypotheses: <integer>
    resolved: <integer>
    matched: <integer>
    falsified: <integer>
    expired: <integer>
    accuracy_rolling_60d: <float 0.0-1.0>
    accuracy_rolling_90d: <float 0.0-1.0>
    last_calibration: <YYYY-MM-DD>
    trend: <improving | stable | degrading | null>
    accuracy_by_tier:
      likely: { n: <int>, matched: <int>, rate: <float> }
      possible-but-surprising: { n: <int>, matched: <int>, rate: <float> }
      unlikely-but-impactful: { n: <int>, matched: <int>, rate: <float> }
```

### Update rules (binding)

- **Updated by `/calibration-report` only.** Never modified manually except via `/shadow-review` dispute workflow (where the principal explicitly overrides a verdict).
- **Append, do not overwrite history.** Per-month rolling-window numbers update; counts are cumulative.
- **`trend: null` while n < 3.** Trend requires three data points minimum.

## monthly/<YYYY-MM>.md — monthly reports

Each month, `/calibration-report` aggregates the previous month's shadow hypothesis resolution into a single report. Format and content follow `memory/templates/calibration-monthly-report.template.md`.

The monthly report is **NOT** the canonical state — `actor-scores.yaml` is. The monthly report is the **narrative summary** of one month's calibration with bias flags, specificity-gate health, triage threshold suggestions, and notable cases.

Cadence: 1st of each month, generated by `/calibration-report`. User reviews + commits.

## actors/<slug>.md — per-actor narrative records (optional)

For actors with **≥5 resolved hypotheses** where the YAML alone doesn't explain the pattern, an optional narrative calibration record can be created. Template: `memory/templates/calibration-actor-score.template.md`.

These records capture:
- Notable hits / misses with traceability
- Identified bias patterns and mitigation hypotheses
- Anti-patterns specific to this actor's predictions
- Re-read-profile recommendations when calibration is degrading

These records are **read at /shadow-review** and inform profile maintenance.

## Bias-watch categories

The framework tracks several bias categories. Each appears in `bias_watch` per-actor when the pattern manifests:

| Bias | Signal | Mitigation |
|------|--------|------------|
| `over-confidence-on-likely` | `likely` hit rate >85% | Tighten tier-label criteria; suspect sandbagging |
| `under-confidence-on-likely` | `likely` hit rate <40% | Re-read actor profile; predicted reactions stale |
| `under-prediction-of-adversarial-moves` | `possible-but-surprising` hit rate of adversarial moves >60% | Reframe relationship_type if it's drifting toward counterparty |
| `channel-specificity-miss` | Direction right, channel wrong | Tighten `expected_signal.source_channels` |
| `actor-direction-flip` | Predictions systematically inverted | Profile sentiment trajectory needs revisit |
| `tier-label-drift` | All tiers hit at similar rates (~50%) | Tier discipline broken; re-derive tier criteria |

The `/calibration-report` agent surfaces these as observation flags; the user applies fixes manually (re-read profile, update template, edit `triage-heuristic.yaml`).

---

## Healthy calibration ranges

Across all actors, healthy per-tier hit rates look like:

- **`likely`:** 60-80% — pattern matches against actor history land most of the time. Above 80% = sandbagging. Below 60% = over-confidence.
- **`possible-but-surprising`:** 20-40% — by definition these are non-default. If hitting >50%, the agent is mis-labeling default-likely moves as surprising.
- **`unlikely-but-impactful`:** 5-15% — by definition rare. If hitting >25%, the tier label is wrong (these are not actually unlikely).

The three-tier framing is a **forecasting calibration tool**, not a guess-the-future tool. The tiers are honest labels about how much surprise the agent expects from the actor.

## Retention

- `actor-scores.yaml` — perpetual. Append-only. Never reset.
- `monthly/<YYYY-MM>.md` — perpetual. Each report is a snapshot of that month's calibration.
- `actors/<slug>.md` — perpetual while actor is active. Moves to `_archived/` when stakeholder profile is archived.
- `audit-log.md` — perpetual. The audit trail of /shadow-review cycles.

---

## Anti-patterns

If you see any of these, calibration discipline has broken:

- Manual edits to `actor-scores.yaml` outside `/shadow-review` dispute workflow
- Monthly report with `overall_accuracy > 80%` and no callout flagging it (governance failure)
- A monthly report with `expired_without_verdict` climbing every month and no specificity-gate tightening suggestion
- Bias-watch entries growing without resolution over multiple cycles
- Per-actor narrative records that read like character assessments (this is a calibration tool, not a portrait gallery)
