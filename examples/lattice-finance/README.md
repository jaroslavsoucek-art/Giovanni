# Lattice Finance — pseudo-fork (filled example)

This directory is a **filled pseudo-fork** of the Giovanni framework on the
synthetic [Lattice Finance domain](../../docs/test-domain.md). It exists to close
**definition-of-done #2** from the framework's `CLAUDE.md`: *"Pseudo-fork test
passes — templates filled for synthetic 2nd domain produce coherent operational
artifacts."*

In plain terms: the framework ships templates. This fork is what those templates
look like once filled with real-shaped content for one coherent domain — a Series
A treasury-automation SaaS run by founder/CEO **Alex Park**. If the templates
forced source-domain-shaped thinking, this fork wouldn't cohere. It does, so the
schemas are generic.

## What this is — and what it is NOT

This is a **content snapshot**, not a runnable repo. It carries only the layers a
fork *fills*:

```
examples/lattice-finance/
├── knowledge/      constitution.md, INDEX.md            ← operating principles
├── memory/         CLAUDE_MEMORY.md (L1), topics/, stakeholders/,
│                   decisions/, branch-out/, shadow/, briefs/,
│                   digest_sources.md, digest_state.md, MAP.md
├── deliverables/   drafted outputs + _registry.yaml
└── docs/           this fork's docs (digest pointer + example transcripts)
```

A **real fork** is a full `git clone` of Giovanni that *also* carries the machinery
this snapshot deliberately omits:

- `scripts/` — the lint + index/map builders + digest dry-run harness
- `.claude/` — agents, commands, hooks, workflows (the actual runtime)
- the full framework `docs/` (policy + rationale: `digest.md`, `prediction.md`,
  `governance.md`, `stakeholder-profiles.md`, …)

This snapshot inherits all of that from the framework root unchanged; it does not
duplicate it. So: this demonstrates **template composition** — that the filled
artifacts cross-reference each other coherently and pass the framework's lint —
**not a live operational instance**. Nothing here runs a digest on its own; the
rendered digest under `docs/` is an illustrative transcript, not state.

## How to validate it

Both commands run from the **Giovanni repo root** (not from inside this directory),
pointing at the fork via `--repo-root`:

```bash
# Governance lint — schema + cross-reference integrity across the fork
python3 scripts/lint.py --repo-root examples/lattice-finance

# Digest dry-run readiness — confirms the /digest pre-flight markers resolve
# (memory/digest_sources.md + docs/digest.md present, state file fresh)
python3 scripts/run-digest-dryrun.py --repo-root examples/lattice-finance
```

The lint enforces, among others: constitution header anchors, digest-state
freshness, shadow-hypothesis horizon/adversarial-check rules, stakeholder and
topic-shard frontmatter validity, that every `key_stakeholders` slug resolves to a
real profile, decision-record trigger conditions, the no-percentages rule in
predictions, the no-recommendation rule in branch-out artifacts, L1 size, and the
deliverables registry ↔ disk consistency.

## Generated snapshots (committed, not hand-authored)

Two files are **committed regenerated snapshots** — they are build outputs, not
sources of truth, and would be regenerated by `scripts/` in a real fork:

- [`knowledge/INDEX.md`](knowledge/INDEX.md) — knowledge-layer index
- [`memory/MAP.md`](memory/MAP.md) — memory-layer map

They are committed here so the snapshot reads as a complete fork without requiring
a build step.

## Why this domain

Lattice is intentionally **different in shape** from the framework's source domain
(different industry, stage, stakeholder dynamics, and time horizon) to stress-test
that the schemas are generic and not implicitly source-shaped. See
[`docs/test-domain.md`](../../docs/test-domain.md) for the full domain definition,
and [`docs/setup-guide.md`](../../docs/setup-guide.md) for the fork-and-fill
process this snapshot is the output of.
